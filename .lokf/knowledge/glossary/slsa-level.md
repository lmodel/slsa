# SLSA level

A level is a step within one [track](slsa-track.md). Higher levels give increasing supply chain security guarantees.

The specification copy defines these levels:

- **Build L0 to L3** (`levels.md`): L0 has no requirements; L1 needs provenance showing how the package was built; L2 needs signed provenance generated by a hosted build platform; L3 needs a hardened build platform.
- **Source L1 to L4** (`source-requirements.md`): L1 uses a version control system; L2 preserves change history and generates source provenance; L3 enforces organizational technical controls; L4 requires code review.
- **Dependency L0 to L4** (`dependency-track.md`): from no mitigations, through an inventory and triaged vulnerabilities, to dependencies consumed from locations under the producer's control, and proactive defence against upstream attack.

The schema encodes the levels as enum values, for example `SLSA_BUILD_LEVEL_2` in `BuildLevelEnum` and `SLSA_BUILD_ENV_LEVEL_0` to `SLSA_BUILD_ENV_LEVEL_3` in `BuildEnvLevelEnum`.
